Section 01

🎯 Project Overview

Problem Statement

Plant diseases cause up to 30–40% crop yield losses globally each year. Smallholder farmers often lack timely access to agricultural experts, resulting in delayed diagnosis and treatment. This project builds an AI-powered, image-based diagnostic system that identifies the crop species and its disease from a single leaf photo, then provides actionable treatment recommendations — all within seconds.

Business / Use-Case Relevance

  • Agriculture: Real-time disease detection for farmers via mobile/web, reducing crop losses.
  • AgriTech Platforms: Embeddable API for precision agriculture dashboards.
  • Government/NGOs: Scalable disease monitoring at the regional level.
  • Education: Training tool for agriculture students and extension workers.

Why Deep Learning?

Traditional rule-based image analysis fails with the visual variability of plant diseases. Convolutional Neural Networks (CNNs) excel at hierarchical feature extraction — learning low-level edges and textures, then composing them into high-level disease patterns. Transfer learning on MobileNetV2 allows us to leverage ImageNet's 14M images while adapting to our domain with a small, focused dataset. Think of it like hiring a doctor who already knows anatomy (ImageNet) and training them to specialize in dermatology (plant leaf diseases).

Section 03

🧠 Model Architecture

Two-Stage Pipeline Design

📷 Leaf Image→ Stage 1: Crop Classifier→ Stage 2: Disease Classifier→ Treatment Lookup

Why two stages? A single monolithic model for all 16 diseases across 3 crops would struggle with inter-crop confusion. By first identifying the crop (3-class), we route to a specialized disease model (3–10 classes), dramatically improving accuracy. Analogy: Instead of one doctor for everything, you see a GP first (crop ID), then a specialist (disease diagnosis).

Base Model — MobileNetV2

ArchitectureMobileNetV2 (inverted residual blocks, depthwise separable convolutions)
Pre-trained OnImageNet (1.4M images, 1,000 classes)
Why MobileNetV2?Lightweight (~3.4M params), fast inference, ideal for deployment on edge/mobile devices
Input Shape(None, 224, 224, 3)

Custom Classification Head

MobileNetV2 base (frozen/unfrozen) → (None, 7, 7, 1280) ↓ GlobalAveragePooling2D → (None, 1280) ↓ BatchNormalization → (None, 1280) ↓ Dense(512, relu) → (None, 512) # Disease model Dense(256, relu) → (None, 256) # Crop model uses 256 directly ↓ Dropout(0.5) → regularization ↓ Dense(256, relu) + Dropout(0.3) → Disease model only (deeper head) ↓ Dense(num_classes, softmax) → (None, C) # C = 3 or 10

Key Architecture Decisions

InitializationImageNet weights (He initialization via Keras defaults for Dense layers)
Loss Functioncategorical_crossentropy — standard for multi-class classification with one-hot labels
OptimizerAdam (adaptive learning rates per parameter; combines momentum + RMSprop)
Output ActivationSoftmax — converts logits to probability distribution summing to 1.0

Two-Phase Training Strategy

Phase 1: Feature Extraction
Base ModelFrozen (all layers)
Epochs10

Phase 2: Fine-Tuning
Unfrozen LayersTop 30 (crop) / 40 (disease)
Epochs20 (crop) / 25 (disease)

Regularization & Callbacks

Dropout0.5 (first layer), 0.3 (second layer, disease model)
Batch NormalizationAfter GlobalAveragePooling — stabilizes activations
EarlyStoppingpatience=5 (Phase 1) / 7–8 (Phase 2), restore_best_weights=True
ReduceLROnPlateaufactor=0.3–0.5, patience=3–4 — halves LR when val_loss plateaus
ModelCheckpointsave_best_only=True on val_accuracy — saves the best model weights
Class WeightsBalanced weighting via sklearn — penalizes misclassification of rare classes
Mixed PrecisionFP16 on GPU — 2× throughput on compatible hardware

Handling Overfitting / Underfitting

  • Overfitting mitigated by: Data augmentation, dropout, early stopping, class weights, two-phase LR schedule
  • Underfitting mitigated by: Transfer learning (pre-trained features), fine-tuning deeper layers, sufficient epochs with patience
  • Monitoring: Train vs. Val accuracy/loss plots saved per model — visual gap inspection

Section 08

⚡ Challenges & Solutions

Class Imbalance

Tomato had 10 disease classes vs. potato's 3. Solved with compute_class_weight("balanced") and per-crop dedicated models.

Multi-Dataset Inconsistency

Different naming conventions across PlantVillage, PlantDoc, TomatoLeaf. Solved with a comprehensive FOLDER_MAPPING dictionary normalizing 30+ folder names.

TensorFlow Mixed Precision Bug

Keras missing quantization_mode attribute. Monkey-patched at import with Policy.quantization_mode = property(lambda self: None).

Real-World Image Quality

Lab images (PlantVillage) differ from field photos. Fused PlantDoc's noisy real-world images + aggressive augmentation to bridge the domain gap.

Section 10

💬 Interview Q&A Preparation

Q: Why did you use a two-stage model instead of one model for all classes?
A single model with 16 output classes across 3 different crops would learn cross-crop confusions (e.g., tomato early blight vs. potato early blight look different but share a label). The two-stage approach first solves a simpler 3-class crop identification problem, then routes to a domain-specific model. This modular design improves accuracy, is easier to debug, and allows independent retraining of each crop's disease model.
Q: Why MobileNetV2 over ResNet or VGG?
MobileNetV2 uses depthwise separable convolutions — reducing parameters from ~138M (VGG16) to ~3.4M while maintaining competitive accuracy. It's designed for mobile/embedded deployment. Since this is a web app that may be deployed on edge devices or resource-constrained servers, MobileNetV2 provides the best accuracy-to-efficiency trade-off.
Q: What is transfer learning and how did you use it?
Transfer learning reuses a model trained on a large dataset (ImageNet) as a feature extractor for a new, related task. I froze MobileNetV2's convolutional layers, added a custom classification head, trained it for 10 epochs, then unfroze the top 30–40 layers for fine-tuning with a 10× lower learning rate. This prevents catastrophic forgetting of the pre-trained features.
Q: How do you handle class imbalance?
I use sklearn's compute_class_weight("balanced"), which assigns higher weights to underrepresented classes during training. This makes the loss function penalize errors on minority classes more heavily. Combined with data augmentation (geometric transforms, brightness shifts), this ensures the model doesn't just memorize the majority class.
Q: What happens if the model gets a non-leaf image?
The system has a 60% confidence threshold. If the crop classifier's top prediction is below this, the response includes low_confidence_warning: true with a message. The frontend shows a warning banner. Additionally, the file validation layer rejects non-image files and enforces a 16MB size limit.
Q: How do you prevent overfitting with limited data?
Five strategies: (1) Multi-source data fusion (PlantVillage + PlantDoc + TomatoLeaf), (2) aggressive augmentation (flip, rotate, zoom, brightness), (3) Dropout (0.5, 0.3), (4) EarlyStopping with patience, (5) transfer learning — the frozen ImageNet weights prevent the model from memorizing noise in our small dataset.
Q: Explain the inference pipeline end-to-end.
User uploads a leaf image via the web UI → JavaScript sends a multipart POST to Flask's /predict endpoint → image is saved to a temp file → PIL opens, converts to RGB, resizes to 224×224, normalizes to [0,1] → Stage 1 crop model predicts crop class → Stage 2 loads the crop-specific disease model and predicts disease → treatment data is looked up from treatments.json → JSON response with crop, disease, confidences, treatment info is returned → temp file is deleted in the finally block.
Q: What metrics would you use to evaluate this in production?
Beyond accuracy, I'd track: (1) Precision per class — critical to avoid false disease diagnoses that cause unnecessary pesticide use, (2) Recall — missing a real disease is costly, (3) F1 for balanced measure, (4) Latency — p50/p99 inference time, (5) Confidence calibration — is 90% confidence actually correct 90% of the time? (6) User feedback loop — tracking misclassifications reported by farmers.
Q: What is Categorical Cross-Entropy and why use it here?
CCE measures the divergence between the predicted probability distribution (softmax output) and the one-hot true label. It's the standard loss for multi-class single-label classification. Mathematically: L = −Σ y_true × log(y_pred). It penalizes confident wrong predictions more heavily than uncertain ones, providing smooth gradients for optimization.
Q: How would you deploy this to production at scale?
I'd containerize with Docker, convert models to TensorFlow Serving or TFLite, deploy behind an API gateway (e.g., AWS API Gateway + Lambda, or GCP Cloud Run). For high throughput, I'd use model batching, GPU inference servers, and a CDN for static assets. The lazy-loading singleton pattern already handles cold start efficiently.

⏱️ 3 MINUTE EXPLANATION

"The problem I'm solving is real-time plant disease detection for farmers who lack access to agricultural experts. Plant diseases cause up to 40% crop losses globally.

Architecture: I designed a two-stage pipeline. Stage 1 is a 3-class crop classifier, Stage 2 is a set of crop-specific disease classifiers (10 classes for tomato, 3 for potato, 3 for corn). Both stages use MobileNetV2 as the backbone — chosen for its lightweight architecture (3.4M params) and depthwise separable convolutions, making it ideal for deployment.

Training: I used a two-phase training strategy — first freezing the base and training only the classification head (10 epochs, LR=1e-4), then fine-tuning the top 30-40 layers with a 10× lower learning rate. I handled class imbalance with balanced class weights and used data augmentation including flips, rotation, zoom, and brightness shifts.

Data: I fused three datasets (PlantVillage, PlantDoc, TomatoLeaf) ~1.8GB total, with a data organization pipeline that normalizes 30+ inconsistent folder names into a unified structure. Images are cleaned, verified, resized to 224×224, and split 80/20.

Deployment: The Flask backend serves a polished web UI. The /predict endpoint accepts image uploads, runs the two-stage pipeline, and returns structured JSON with crop, disease, confidence scores, and treatment recommendations from a curated database. Temp files are cleaned post-inference."

⏱️ DEEP TECHNICAL EXPLANATION

Data Pipeline: organize_datasets.py merges PlantVillage (~54K images), PlantDoc (~2.5K real-world), and TomatoLeaf (~10K) into a unified data/raw/{train,val}/{crop}/{disease}/ structure. A comprehensive FOLDER_MAPPING dictionary handles 30+ inconsistent folder names across sources. Images are verified with PIL, converted to RGB, resized to 224×224 with Lanczos resampling, and saved at 95% JPEG quality. The split is 80/20 with seed=42.

Model Architecture: MobileNetV2 backbone pretrained on ImageNet (1.4M images). The custom head is: GlobalAveragePooling2D → BatchNorm → Dense(512, ReLU) → Dropout(0.5) → Dense(256, ReLU) → Dropout(0.3) → Dense(num_classes, Softmax). The disease model has a deeper head (512→256) than the crop model (256 directly) because it has more nuanced classes to separate.

Training Strategy: Two-phase: (1) Frozen backbone, Adam optimizer at LR=1e-4, 10 epochs with EarlyStopping(patience=5). (2) Unfreeze top 30-40 layers, reduce LR to 1e-5 (prevents catastrophic forgetting), 20-25 epochs with EarlyStopping(patience=7-8), ModelCheckpoint(save_best_only), ReduceLROnPlateau(factor=0.3, patience=4). Class weights computed via sklearn's balanced mode. Mixed precision (FP16) enabled on GPU for ~2× throughput.

Inference: Lazy singleton pattern loads models on first request and caches in module-level globals. Input: PIL → RGB → resize 224×224 → normalize [0,1] → expand_dims → model.predict(verbose=0). The crop prediction is decoded via a class→index JSON mapping (inverted at runtime). The predicted crop routes to the corresponding disease model. Predictions below CONFIDENCE_THRESHOLD=0.60 raise a warning flag. Treatment metadata is looked up from treatments.json (468 lines, covering symptoms, treatment, prevention, severity for all diseases).

Application Layer: Flask with factory pattern (create_app), AppConfig dataclass loaded from env vars (12-factor), CORS enabled, structured error responses with error codes. Temp files via tempfile.mkstemp() deleted in finally block. Health endpoint reports startup readiness, missing files, and TF compatibility warnings. Test suite uses pytest with mocked prediction module (no TF dependency in tests).
